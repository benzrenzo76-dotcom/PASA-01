# Simulador HTTP separado — SIMULACIÓN

**POSIBLE NO DEMOSTRADO** — Representa exclusivamente una futura respuesta HTTP del backend. No es USSD extremo a extremo ni lo llama Android. Sin integración bancaria ni datos financieros.

Desde la raíz: `python3 gateway-simulator/server.py`. En otra terminal: `curl http://127.0.0.1:8081/simulated/diagnostic`. Sólo escucha en loopback. Para pruebas: `python3 -m unittest discover -s gateway-simulator -v`.

**DEPENDE DE TERCEROS** — Un adaptador empresarial futuro necesitaría contrato con operadora/agregador, código asignado y autorizado, endpoint documentado para webhook y respuestas, autenticación acordada, límites de sesión/codificación, identificación segura, protección de replay y entorno de pruebas. Este endpoint local no es un endpoint de una operadora. El servidor Python conserva el ejemplo HTTP inicial; las fallas configurables y el adaptador HTTP ejecutable están en el módulo TypeScript descrito abajo.

## Red y gateway TypeScript v0.1

**DEMOSTRADO POR PRUEBA** — `npm ci && npm test` compila `src/index.ts` y ejecuta pruebas unitarias y dos pruebas E2E HTTP reales contra el motor SQLite de `backend/`. Primero ejecutar `npm ci && npm run build` en `backend/`. Las pruebas no llaman una operadora. La ejecución local del 2026-10-24 pasó 9 tests, incluidos pérdida de confirmación tras un débito real ficticio, consulta de estado y replay sin segundo débito, y rechazo bancario inyectado por HTTP sin movimientos.

**POSIBLE NO DEMOSTRADO** — Para una demostración manual, iniciar el backend de laboratorio en loopback y ejecutar aquí `npm run demo -- http://127.0.0.1:8080`. Envía una transferencia ficticia de $5.000; no reinicia saldos automáticamente. El demo sólo acepta loopback y nunca envía códigos a una red móvil. `VirtualUssdGateway` realiza `fetch` real hacia la API; `VirtualNetwork` representa las etapas celulares con eventos generados durante la ejecución.

**POSIBLE NO DEMOSTRADO** — `VirtualNetwork.run(operationId, phase, action)` entrega eventos con timestamp, secuencia, estado y tiempo relativo. El callback recibe indicación de duplicado y rechazo bancario artificial; el motor debe implementar idempotencia. `VirtualUssdGateway.request` propaga rechazo bancario mediante `rejectBank:true` a la API de laboratorio, que conserva sus validaciones. El resultado de transporte `DELIVERED` significa respuesta entregada; hay que leer el estado financiero devuelto. Un fallo tras enviar o una confirmación perdida entrega `PENDING` y oculta la respuesta; el cliente debe consultar `GET /operations/:id`, nunca crear otra operación para reintentar el débito.

**POSIBLE NO DEMOSTRADO** — Configuración reproducible: semilla entera, demoras fijas o rango+jitter, pérdida, timeout después del procesamiento, duplicación, retención de respuesta que permite sobrepasos entre solicitudes concurrentes, fallas de gateway/API antes de enviar, rechazo bancario y demora de servidor. Desactivar `enabled` desactiva toda inyección. Los eventos permanecen ordenados por su ocurrencia observada; no se falsifican timestamps para representar reordenamiento. `measuredElapsedMs` mide pared monotónica incluyendo esperas; `measuredActionMs` mide sólo la acción real; `measuredWaitMs` mide la espera efectivamente ejecutada y `artificialDelayMs` es el presupuesto solicitado. No promediar esas categorías juntas. `exportRun` excluye respuesta y autorizaciones; las vistas consumidoras deben usarlo al exportar trazas.

**NO VERIFICADO** — El perfil `PASA-01 Observado` usa 300 ms artificiales como ejemplo. Los valores 190, 300, 436, 1350 y 1915 ms y API 36 fueron reportados por el fundador para diagnóstico real, no medidos por este módulo ni validados contra informes adjuntos. No constituyen una distribución estadística, ni percentiles reales, ni tiempos de una transferencia bancaria.

**CONFIRMADO EN DOCUMENTACIÓN** — Referencia técnica consultada en esta sesión el 2026-10-24: ETSI TS 23.038, https://www.etsi.org/deliver/etsi_ts/123000_123099/123038/16.00.00_60/ts_123038v160000p.pdf. USSD admite un presupuesto de hasta 160 octetos; el alfabeto y los caracteres de extensión cambian la capacidad útil. 182 caracteres no es un límite universal de ASCII. El sobre experimental `V1:E:operationId` se restringe a letras, números, dos puntos, guion y guion bajo y sólo lleva correlación, no autorización. **NO VERIFICADO** — Que la solicitud financiera completa y su autorización quepan en una pasarela comercial. No existe continuidad interactiva real ni integración con operadoras en este módulo.
